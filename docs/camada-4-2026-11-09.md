## 2. Implementação (skill de backend)

Arquivos alterados: `scripts/check-audit-quotes.py`, `scripts/run-evals.py`, `scripts/quality-gate.py`.

O que a skill obrigou a fazer diferente do plano inicial:

- **contrato antes do código** — o exit code foi decidido antes da implementação, não depois;
- **controle negativo obrigatório** — testar só o caso que passa não prova nada; o laudo inválido é o teste
  que importa (mesma lógica de "teste que passa com o produto quebrado");
- **não desabilitar verificação para obter verde** — quando `reaudit-11` passou a acusar 25 fabricações, a
  tentação era afrouxar o limiar. A decisão foi investigar: eram **anotações do auditor e linhas quebradas**,
  não citações inventadas. Corrigir o extrator ≠ afrouxar o critério.

## 3. O loop (skill autônoma)

### Baseline (antes de tocar em nada)

```
gate:        15/15
evals check: 131 casos · 0 erros · 3 avisos
quotes:      reaudit-5  -> exit 2 (nenhuma citação longa encontrada)
             reaudit-11 -> exit 2 (idem)
             audit-2026 -> exit 1 (16 de 16 com fabricação)
```

**O baseline expôs o defeito que a tarefa resolveria**: a ferramenta não lia o formato dos laudos válidos.
Exit 2 nos dois laudos que deveriam passar.

### Iterações (5 correções, todas com defeito real)

| # | Sintoma | Causa | Correção |
|---|---|---|---|
| 1 | `reaudit-5/11` → exit 2 | regex de cabeçalho só aceitava `###`, os laudos usam `##` | `#{2,4}` |
| 2 | `reaudit-11` → 25 fabricadas | extrator pegava o bloco inteiro, incluindo citação do **input antigo** | isolar a seção de resposta |
| 3 | `reaudit-11` → 6 fabricadas | anotações `(checklist de 6 itens…)` contadas como citação | classe `RESUMO` |
| 4 | `reaudit-5` → 2 fabricadas | linha de citação quebrada em duas no laudo | juntar linha seguinte antes de acusar |
| 5 | selftest quebrado | guarda de tamanho matava citação curta legítima | remover guarda; comparar com anotações removidas dos dois lados |

### Reteste

```
--verify-quotes                              -> exit 0  (reaudit-5: 42 verbatim · reaudit-11: 22 + 6 resumo)
--verify-quotes --laudo audit-2026-...md     -> exit 1  (54 de 68 fabricadas)
gate                                          -> 16/16
```

## 5. O que quebrou

Nada quebrou em produção — mas **cinco vezes a ferramenta acusou o laudo válido** durante a construção. Se
eu tivesse confiado na primeira saída (`16 de 16` no laudo original e `25 fabricadas` no reaudit), teria
publicado uma ferramenta que reprova evidência legítima — e a conclusão errada seria "a re-auditoria também
fabricou".

Esse é o retrabalho que a Camada 4 cobra: não é parágrafo de auditoria, é tempo de depuração.

## 6. O que funcionou

| Item | Evidência |
|---|---|
| Spec antes do código | o contrato de exit code impediu divergência entre script e comando |
| Controle negativo | foi ele que provou que a ferramenta discrimina (exit 1 só no laudo inválido) |
| Baseline primeiro | revelou que a ferramenta não lia o formato dos laudos válidos (exit 2) |
| Gate como consequência | `evals:citacoes` no `quality-gate.py` → CI verde é a prova, não a minha palavra |

## 7. Lições

1. **Verificar citação é parsing de dialeto, não comparação de string.** Cinco iterações para lidar com
   cabeçalho `##` vs `###`, anotação entre parênteses, linha quebrada e code-span. Um teste só com o caso
   feliz teria escondido todos os cinco.
2. **A ferramenta que acusa precisa ser testada contra o caso que deve passar.** Meu primeiro instinto foi
   celebrar "25 fabricadas". Era falso positivo.
3. **Skill de backend mudou a decisão**: contra a vontade de afrouxar o limiar para ficar verde, a regra
   "nunca desabilite verificação para obter verde" apontou o caminho certo — corrigir a extração.
4. **Camada 4 não substitui as outras, mas cobra de outro jeito**: o erro aqui custou iteração, não reputação.
   É o tipo de custo que faz o método valer.

## 8. O que NÃO foi testado

- Laudo em formato diferente dos dois usados (ex.: YAML, tabela sem blockquote) → o tool devolve exit 2
  "sem citação longa", não falha silenciosa, mas também não verifica.
- Citação correta com reordenação de palavras → classifica como `FABRICADO` (o teste é por sequência de 4
  palavras). Limite conhecido.
- CI em runner Linux: o workflow roda lá desde a v1.3.0, mas este commit específico só é provado depois do
  push.
